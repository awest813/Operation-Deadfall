# Asset Reference Audit — quakec/deadfall

Generated by a cross-validation of every asset path string literal in
`quakec/deadfall/` (server QC + CSQC, 634 unique references) against the
actual game data an end user gets:

- **NZ:P nightly** (`nzportable-linux64.zip`, the bundle `setup_game.sh` /
  `scripts/setup_game.ps1` download) — 1151 loose files under `nzp/`.
- **LibreQuake v0.09-beta** (`mod.zip`, the optional `lq1/` layer) — 524
  files including both paks' internal directories.

**Result: 367 references resolve, 0 case mismatches, 267 reference files
that exist in neither data source.** The engine degrades gracefully (missing
models show the error model, missing sounds are silent), so the game runs,
but these assets are genuinely absent content.

This audit led to the following code changes (already applied):

- All purchase/deny/pickup/streak/round-flow and footstep sounds now point at
  paths that exist in stock NZ:P data (`sounds/misc/buy.wav`,
  `sounds/misc/denybuy.wav`, `sounds/misc/ching.wav`, `sounds/menu/*.wav`,
  `sounds/rounds/nround.wav`, `sounds/player/footstep1-4.wav`,
  `sounds/player/pickup.wav`, `sounds/misc/electric_bolt.wav`).
- The id1/`precache_file("maps/*.bsp")` boilerplate inherited from upstream
  QuakeC is harmless (it is a hint, not a requirement) and was left alone.

What remains missing, by category, for content authors who want to close the
gap — highest player-visible impact first:

## 1. Weapon view/world models (43 refs)
Every weapon's first-person view model (`progs/v_*.mdl`) and world model
(`progs/w_*.mdl`) referenced by `inventory.qc`. NZ:P ships its own weapon
models under `models/weapons/` with NZ:P names (`m1911`, `mp40`, ...), so
closing this gap is a per-weapon remap/rename job, not a file copy.

literals and re-run a case-insensitive existence check (see the
`nzp/`-validator used for this pass). Re-run after adding content to confirm
new references resolve.
